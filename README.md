# speedtest

Замер скорости интернет-соединения: скрипт последовательно скачивает файл по заданному
URL, замеряет время и объём каждой загрузки и печатает итоговую пропускную способность.

Зависимости: только стандартная библиотека Python 3.10+.

## Запуск

```bash
python speedtest.py <URL>
```

| Параметр | Назначение |
| --- | --- |
| `-n`, `--count` | количество запросов (по умолчанию 10) |
| `--timeout` | таймаут одного запроса в секундах (по умолчанию 30) |
| `--chunk-size` | размер буфера чтения в байтах (по умолчанию 65536) |
| `--warmup` | прогревочный запрос вне статистики |
| `-v`, `--verbose` | уровень логов DEBUG |

Пример:

```bash
python speedtest.py https://example.com/heavy.jpg -n 10 --warmup
```

```

...
```

## Методология замера

**Скорость = суммарный объём / суммарное время**, а не среднее скоростей отдельных
запросов. Среднее арифметическое по отношениям завышает вклад коротких быстрых
запросов и не равно фактической пропускной способности. Разницу фиксирует тест
`test_throughput_is_total_bytes_over_total_time`.

**Запрет кэширования.** Десять запросов к одному URL охотно отдаются CDN или
корпоративным прокси из кэша — замер показал бы скорость кэша, а не канала. Поэтому
отправляются заголовки `Cache-Control: no-cache` и `Pragma: no-cache`.

**Тело ответа не сохраняется.** Данные читаются буферами и отбрасываются: запись на
диск добавила бы в замер скорость диска, а накопление в памяти упёрлось бы в RAM на
больших файлах.

**Прогрев — опционально.** Первый запрос платит разовые издержки, которых нет у
остальных: DNS-резолв (дальше имя в кэше ОС), возможный холодный edge CDN и
заполнение кэша TCP-метрик маршрута. Один такой выброс заметно смещает среднее по
десяти замерам, поэтому флаг `--warmup` делает запрос вне статистики. По умолчанию он
выключен, чтобы поведение точно соответствовало условию задачи («10 запросов»).

Важно, чего прогрев **не** убирает: `urllib` не переиспользует соединения (отправляет
`Connection: close`), поэтому TCP- и TLS-хендшейк и TCP slow start заново
оплачиваются каждым запросом, а не только первым. На коротких файлах это означает,
что замер во многом упирается в задержку установки соединения, а не в пропускную
способность — отсюда рекомендация брать файл покрупнее (десятки мегабайт).

**Медиана рядом со средним.** Среднее по десяти замерам смещается одним выбросом
(ретрансмиссия, чужой трафик в канале), медиана — нет. Расхождение между ними само по
себе сигнализирует о нестабильности канала.

**Единицы.** `1024²` байт — это мебибайт, а не мегабайт, поэтому в отчёте `МиБ/с`.
Рядом печатается `Мбит/с`: провайдеры указывают скорость именно в мегабитах, и это
число можно напрямую сравнить с тарифом.

## Потоки вывода

Диагностика (ход выполнения, ошибки) пишется в **stderr** через `logging`, итоговый
отчёт — в **stdout**. Это разные по смыслу каналы: лог сопровождает выполнение, отчёт
является результатом. Поэтому результат можно забрать отдельно:

```bash
python speedtest.py <URL> 2>/dev/null
```

Код возврата: `0` — успех, `1` — ни один запрос не выполнен.

## Обработка ошибок

Упавший запрос логируется на уровне `ERROR` и пропускается, серия продолжается —
одна сетевая ошибка не должна обнулять весь замер. В отчёте видно, сколько запросов
из запрошенных прошло успешно. Перехватывается `OSError`: он покрывает `URLError`,
`HTTPError`, `TimeoutError` и обрыв соединения в середине скачивания.

## Тесты

```bash
python -m unittest -v
```

Чистые функции `summarize` и `format_report` тестируются без сети. Загрузка
проверяется интеграционно против локального `http.server` на случайном порту —
тесты не зависят от внешних хостов и проходят офлайн.

## Ограничения

- Измеряется только скачивание (download), не отдача.
- Одно соединение в один поток не насыщает широкий канал: на скоростях порядка
  сотен Мбит/с упор будет в задержку и размер TCP-окна, а не в пропускную способность.
  Публичные speedtest-сервисы качают в несколько параллельных потоков; здесь запросы
  последовательные, как того требует условие задачи.
- Результат включает время установки соединения (без `--warmup`) и зависит от того,
  насколько близко расположен сервер, отдающий файл.
